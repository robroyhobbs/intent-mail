A New Paradigm: DocOps

Documentation is not "written" — it's a byproduct of engineering state. Replayable, with provenance, same-source as code, and memory for agents.

📐 Structure-First Design

Focus on content and semantics. Let Theme + AI handle the visual layer naturally. Pure semantic structure without styling props polluting your content.

🌱 The Garden Metaphor

You decide where the trees go, where paths wind. AI handles the leaves and flowers. Define the aesthetic baseline, let nature do the rest.

🔄 Version-Controlled Workflow

Every change is atomic, diffable, and auditable. Batch feedback, not real-time commands. AI as a peer collaborator, not a tool to command.

📁 Page = AFS Structure

Pages are AFS structures, not HTML. AI understands semantic structure directly without parsing. Blocklets mount to AFS with both model and view.

The Smith Workflow

Version-controlled collaboration between you and AI. No real-time commands — structured, batch-based iteration.

1

V0: Input

Provide source material, configuration, and data sources

2

V1: Generate

DocSmith produces the first complete version

3

V1.5: Feedback

Batch your feedback — global, local, or direct patches

4

V2+: Iterate

New versions with diff views. Repeat until done.

Core Principles

✓

AI never modifies your original input

Your source material stays untouched. All changes happen in DocSmith's versioned workspace.

✓

Every feedback is a batch patch

Global semantic, local rewrite, or direct change — all feedback becomes structured patches.

✓

Every version is complete and exportable

No partial states. Each version stands alone. Export whenever you're ready.

✓

Workspace isolation

DocSmith works in its own directory. Your repos stay clean and unaffected.
